# Design

## Context

See `proposal.md` — Why. The repo currently has per-library unit suites and a
`server/tests/` HTTP suite that mocks `geomemory`/`geoagent` facades. Nothing
exercises the real seams. This change adds a repo-root `tests/integration/`
suite that runs the gateway against a real `GeoMemory` workspace and real
`geoagent` tooling, with synthetic data only.

Constraints:
- `geospatial` conda env only (per `AGENTS.md`).
- No network: no Planetary Computer, no Open-Meteo, no remote LLM. The QA
  path must use a local/mock LLM backend so `ask` returns citations without
  hitting an external API.
- No real satellite rasters: synthetic GeoTIFF fixtures generated on the fly.

## Goals / Non-Goals

**Goals:**
- Prove gateway↔`geomemory` ingest/search/ask works with real facades.
- Prove `geoagent` can run a tool against a real ingested workspace.
- Prove SQLite writes serialize under concurrent gateway requests.
- Prove `geoagent` GIS tools consume data-engine-style outputs from
  synthetic rasters + `sample/sasmple.geojson` ROI.

**Non-Goals:**
- Real satellite fetch (Planetary Computer / STAC) — separate change.
- Real weather fetch (Open-Meteo) — separate change.
- Real LLM provider roundtrip — use local/mock backend only.
- Web E2E (Playwright) — separate change.
- data-engine METRIC pipeline end-to-end — separate change.

## Decisions

### D1: Repo-root `tests/integration/`, not per-lib

A single suite shares one conftest that owns the temporary workspace root and
the gateway process. Per-lib suites cannot see cross-lib seams. Root-level
keeps the "gateway calls real `geomemory`" assertion in one place.

### D2: Run the gateway in-process via `TestClient`, not a subprocess

`server/src/geofront_api/main.py` is a FastAPI app. `starlette.TestClient`
runs it on the event loop without binding a port. This avoids flaky port
allocation and lets tests assert on the real `AppState.write_lock` object
directly for the concurrency gate.

Alternative considered: subprocess `uvicorn` + `httpx`. Rejected — slower,
flakier, and the `AppState` lock is not observable from outside.

### D3: Mock LLM backend for `ask`, real retrieval for search

`geomemory.qa.backend_factory.build_llm_backend()` reads `llm_provider` from
workspace settings. The integration conftest sets `llm_provider="api"` with a
`GEOMEMORY_LLM_API_KEY` pointing at a stub, or better, monkeypatches
`build_llm_backend` to return a deterministic `LLMBackend` that echoes the
context. Search and indexing use real `geomemory` backends (ONNX/hashing),
so the retrieval half of the provenance chain is genuinely exercised.

Alternative: skip `ask` entirely. Rejected — the provenance chain is the
highest-value seam and skipping it defeats the purpose.

### D4: Synthetic rasters generated by `rasterio` in fixtures

A small helper writes a 4-band synthetic GeoTIFF (red, green, NIR, SWIR)
over the bounds of `sample/sasmple.geojson` so zonal stats are meaningful.
No disk fixtures committed; generated per-test under `tmp_path`.

### D5: Reuse `server/tests/conftest.py` workspace fixture

Extract the workspace-creation helper from `server/tests/conftest.py` into a
shared module importable by both suites, so the integration tests do not
duplicate workspace bootstrap logic.

## Risks / Trade-offs

[Risk: ONNX model download on first test run] → Mitigation: set
`embedding_provider="hashing"` in the integration workspace settings so no
model download occurs; hashing embedder is deterministic and sufficient to
exercises the dense search path.

[Risk: `ask` with a stubbed LLM may mask real LLM-failure modes] → Mitigation:
the stub still goes through `ChatService` → `context_packer` → citation
mapping, so the provenance chain is real even if the text is synthetic.

[Risk: concurrent-write test may be flaky on slow CI] → Mitigation: use a
small N (8) and assert only on final row count + absence of `database is
locked` errors, not on timing.

[Risk: `sample/sasmple.geojson` is a single polygon with no raster overlap]
 → Mitigation: the synthetic raster is generated to cover the AOI bounds, so
zonal stats are well-defined.
