## A — Explicit user requests (001–005)

**A-001 · Custom provider (name + base URL + API key) cannot be added in Settings** —
`apps/studio/src/components/ProviderPicker.tsx:143-152` sends only `llm_provider/llm_model_id/llm_api_base_url/llm_api_key_env` (no `llm_api_key`); `schemas.py:93-96` accepts `llm_api_key` but UI never sends it; `routers/providers.py:42-46` hardcodes only OpenAI/OpenRouter; `:69` rejects any other URL. `llm_provider` pattern `^(api|llamacpp)$` (`schemas.py:90`) collapses every provider to "api". **VERDICT: confirmed, exactly as reported.** Effort L · Risk MED · Conf HIGH. Fix: governed `POST /providers` (name/HTTPS base/key), widen persisted provider identity, add password key input wired to `llm_api_key`, keep operator allow-list optional.

**A-002 · Scene previews never show for real search results** —
`SceneRef` has no thumbnail field (`libs/data_engine/src/data_engine/fetch/types.py:36-46`); MPC `rendered_preview` assets discarded at `planetary_computer_fetcher.py:404,990`; `/data/search` returns bare `asdict(ref)` (`routers/data.py:70`); Studio maps live scenes with no image URL and renders literal "No scene preview available" (`AcquireView.tsx:193`, `lib/api.ts:124-133`, `lib/types.ts:49-59`). **Confirmed.** Effort M · Risk LOW · Conf HIGH. Fix: optional `preview_url` on `SceneRef`, populate from STAC, optional `GET /data/scenes/{id}/preview`, render `<img>` with fallback.

**A-003 · No way to change bands / custom RGB after download** —
`tileUrlFor(relPath, bands="1")` default single band (`lib/api.ts:180-183`), no call site passes RGB; download preview hardcodes `result.band_files.blue` (`AcquireView.tsx:88-99`); tiles route takes numeric indexes into one file (`routers/data.py:116`); `fetch_scene` has no `bands` param (`fetch/api.py:71`); only RGB compositor requires `['blue','green','red']` and makes a matplotlib figure (`output/visualization.py:509`). **Confirmed.** Effort M–L · Risk MED · Conf HIGH. Fix: persist `band_map`, add composite tile endpoint (multi-source VRT + per-channel stretch), R/G/B selectors in layer tree, rebuild tile URL with `r,g,b`.

**A-004 · Sentinel-1 support not present in GeoMind data_engine** —
GeoMind `SENSORS = ("landsat","sentinel")` (`fetch/api.py:24`), gateway `Literal["landsat","sentinel"]` (`schemas.py:213,224`), agent tool enum (`services/agent.py:292`), Studio sensor list (`AcquireView.tsx:9`) all exclude S1. GeoDataEngine has full S1 port at `D:\RS\Projects\GeoDataEngine\src\data_engine\io\planetary_computer_fetcher.py:1278-1878` (GRD `sentinel-1-grd` + RTC `sentinel-1-rtc`, vv/vh polarizations, `sentinel1_<date>_<orbit>` dirs, GDAL TPS geolocation, no cloud cover). **Critical porting constraint:** GeoMind's base fetcher is strictly typed with the CRS-window fix (`_bounds_in_crs` `:734`), lazy `_catalog()` (`:193`) and `min_coverage_ratio=0.9`; GeoDataEngine's base is an older fork that regressed all three — port ONLY the S1 block, never copy the file. Effort L · Risk HIGH · Conf HIGH. Full 12-item porting checklist in §"Porting checklist" below.

**A-005 · Landsat 8 and 9 shown as two separate search options** —
`AcquireView.tsx:9` has "Landsat 9 OLI-2/TIRS-2" and "Landsat 8 OLI/TIRS" as separate options; backend is already unified (`collection="landsat-c2-l2"` at `planetary_computer_fetcher.py:162`; `fetch/api.py:24` one `"landsat"` sensor; GeoDataEngine `catalog.py:72-73` both → `landsat-c2-l2`). Fix: replace the two options with one "Landsat 8/9 (Collection 2 L2)"; no dedupe needed (STAC IDs are globally unique).
