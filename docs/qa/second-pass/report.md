مبنای بررسی: `0417676`؛ build تولیدی بدون DEMO، Chromium واقعی، دسکتاپ ۱۴۴۰×۹۰۰ و موبایل ۳۹۰×۸۴۴. در سناریوی آفلاین درخواست‌ها قطع شدند؛ در سناریوی متصل، مرورگر پاسخ‌های HTTP/SSE کنترل‌شده دریافت کرد. این گزارش تست سرویس تجاری نیست. **B** یعنی اثر در اجرای مرورگر مشاهده شد؛ **C** یعنی مسیر خطا در کد شناسایی شد و سناریوی ستون دوم برای بازتولید مستقل است، نه ادعای اجرای آن. اولویت P1 = نتیجه یا عمل گمراه‌کننده/مانع کار؛ P2 = اختلال محدودتر. ستون آخر رفتار قابل قبول برای تست اصلاح است. این‌ها یافته‌های جدیدند، نه تکرار فهرست ۲۸ تغییر؛ چند مورد اثر جانبی یا مسیر جاافتادهٔ همان قابلیت‌ها هستند.

### بازتولید

از ریشهٔ مخزن، `cd apps/studio && npm run build` (بدون `VITE_GEOMIND_DEMO=1`). سپس در ریشه `NODE_PATH=/tmp/qa/node_modules LD_LIBRARY_PATH=/tmp/al/lib node scripts/qa/second-pass.cjs`؛ مسیرهای موقت مربوط به نصب `puppeteer-core@24` و `@sparticuz/chromium@141` طبق راهنمای ممیزی قبلی هستند. اسکریپت سرویس خارجی را فراخوانی نمی‌کند و عکس‌ها و گزارش خام را بازنویسی می‌کند. برای triage ابتدا ۰۱، ۰۸، ۱۳–۱۴، ۱۶ و ۲۹ بررسی شوند: این موارد می‌توانند کار، مقصد یا شاهدی متفاوت از آنچه کاربر می‌بیند ایجاد کنند.

## پس از اصلاح

هر ۵۰ ردیف بالا در این شاخه اصلاح شد؛ جدول برای مقایسه حفظ شده است. تصاویر «پیش/پس» در git نگهداری نمی‌شوند و با `scripts/qa/second-pass.cjs` محلی بازتولید می‌شوند؛ [دادهٔ خام مرورگر پس از اصلاح](after/observations.json) در پوشهٔ `after` باقی مانده است. اسکریپت اکنون به‌جای بازنویسی عکس اولیه، خروجی جدید را آنجا می‌نویسد و برای عرض موبایل، جدایی پیام‌ها، خطای قابل‌مشاهده، Escape و مسیر ناشناخته assertion دارد. در Ops برای کاری که gateway API لغو ندارد دکمهٔ لغو ساختگی نمایش داده نمی‌شود؛ در Acquire تلاش مجدد یک دانلود واقعی با شناسهٔ سرور می‌سازد. این آزمون مرورگر از APIهای کنترل‌شده استفاده می‌کند؛ با تأیید زندهٔ سرویس‌های بیرونی یا اجرای ۵۰ سناریوی مستقل برابر نیست.
