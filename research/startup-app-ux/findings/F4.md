# F4 — Local-first & offline AI app UX patterns

Sources: Ink & Switch "Local-first software" (2019); Obsidian architecture/docs; Notion offline mode + CRDT posts (2025-12, 2026-09); Smashing Magazine local-first web dev (2026-05); Expo local-first docs; sujeet.pro offline-first architecture (2026-02); LM Studio / Ollama / Jan public docs; interface lineage local-first sync.

## 1. Core principle: local-first is a data architecture, not a cache

- Client holds the **primary copy** of user data; server is a **sync peer**, not gatekeeper.
- Reads/writes hit local DB first; sync runs in background off the critical path.
- "Offline-first (cache)" queues server writes; "local-first" lands writes on client first. Different regimes.
- Ink & Switch 7 ideals (target gradient, not binary): (1) no spinners, (2) work not trapped on one device, (3) network optional, (4) seamless collaboration, (5) long-term preservation, (6) security/privacy by default, (7) ultimate ownership/control. Most production apps hit 1–4 + partial 5.

## 2. Obsidian patterns (local-first gold standard for single-user)

- **"Files over app"**: vault = folder of plain Markdown; files are truth, app is a viewer. No DB, no migration, copy folder = portable.
- No account required; works offline forever; sync is opt-in paid (E2E) or third-party (Git/Syncthing/iCloud).
- Privacy as structural property: app makes no network calls unless user opts in — verifiable, not marketing.
- Plugin-first: core small; ~2000 community plugins; nothing forced without opt-in.
- **Quick Capture**: write from lock screen/control center/widgets without loading vault (solves slow vault startup). "Launches faster than iOS animation." Captures go to Inbox with auto titles.
- **fs.watch** detects external changes (Git pulls, manual edits) → re-index + UI update.
- Metadata cache for fast link/tag/frontmatter lookup.
- **Exclusions as privacy boundary**: excluded folders not indexed, don't appear in connections/lookup, not embedded. Two control layers: indexing controls (what gets processed) vs result filters.
- Note-first retrieval: start with one note → related notes → small context bundle; don't "chat with whole vault" first.
- Onboarding pain: empty vault + steep curve; plugin/theme discovery bad. Mobile trails desktop.
- Performance degrades at 10k+ notes.

## 3. Notion offline patterns (multi-user cloud app retrofitting offline)

- **Per-page "Available offline" toggle** (••• menu) with download progress bar; offline tab in Settings lists downloaded-by-you vs auto-downloaded.
- **Forest of offline page trees**: SQLite tracks pages available offline + reasons (toggled, auto, inheritance). Page removed only when last reason disappears. Hierarchical inheritance for DB rows/children.
- **Refusal to render partial data**: if a page may be missing transitively required blocks, show "unavailable offline" rather than broken/partial content. Missing data worse UX than unavailable.
- **Push-based updates** via pub/sub channels per page (not polling). On reconnect, compare `lastDownloadedTimestamp` vs server `lastUpdatedTime`; fetch only moved pages.
- **CRDT migration** for offline-marked pages: rich text concurrent edits merge automatically; non-text properties (select) can still surface conflicts.
- **Search shows ready first**, unavailable greyed out — focus on what you can work on now.
- **Sync status indicator** confirms up-to-date; auto-merge text edits, non-text (images) may need review.
- Auto-download recent + favorited pages on Business/Enterprise plans.
- Offline limitations surfaced: can't share/change permissions; embeds/forms/buttons unavailable.

## 4. Local AI app patterns (Ollama / LM Studio / Jan)

- **Zero-friction install**: one-click model download + run; no terminal required; GUI for model management.
- **Offline by default, no telemetry, no login, no data collection** — privacy as default (matches Obsidian structural privacy).
- **OpenAI-compatible local API** so apps can swap remote↔local transparently (GeoMind already does hybrid remote/local GGUF).
- **Model management UI**: discover, install, update, delete models; show VRAM/RAM requirements; running status.
- **Chat interface + history** stored locally; export options.
- **Jan**: open source, 100% offline, connect to cloud optionally.
- **LM Studio**: desktop app, "Bionic" agent; model systems; OpenAI-like endpoints.
- **Locally AI (LM Studio iOS)**: best design/implementation for mobile local AI — shows mobile local AI is viable.
- Community clients (Open WebUI) layer ChatGPT-like UX on top of Ollama — separation of runtime vs UI.

## 5. Conflict resolution & sync UX

- **Two consistency regimes**: server-ordered online (no timestamps/CRDT needed) vs CRDT-merged offline. Name them explicitly.
- CRDTs: commutative/associative/idempotent merge; no conflict logic needed; ideal for offline-first with unpredictable merge timing. Trade memory for simplicity (tombstones).
- Decision matrix: LWW (simple, lossy, key-value), OT (real-time collab, needs server), CRDT (offline-first, P2P).
- **Optimistic local state**: apply mutations immediately; rollback on rejection.
- **Connection resilience**: exponential backoff with jitter; heartbeats; reconnect without data loss.
- **UI must distinguish**: local-saved vs syncing vs remotely-confirmed vs action-required. Pending change count. Conflict indicators with inline resolution (keep local / accept remote / manual merge).
- **Graceful degradation**: if conflict can't auto-resolve, present conflict state preserving both versions; keyboard-operable resolution.
- **Accessibility**: sync status in text (not only color); offline banners must not cover focused controls or erase workflow.

## 6. UX anti-patterns to avoid (from research)

- Spinners for data already on device (violates "no spinners" ideal).
- Treating offline as degraded mode / "offline! warning!" blocking work.
- Showing partial/missing data instead of "unavailable" (Notion lesson).
- Requiring account/login before first use (violates "local first" literal definition).
- Polling instead of push for offline page freshness.
- Clearing outbox on logout without preservation policy.
- Assuming local storage permanent (Safari evicts after 7 days no interaction; quota limits).
- Slow vault/app startup blocking quick capture (Obsidian's mobile flaw → Quick Capture fix).
- Bad discovery of features/plugins (Obsidian complaint).

## 7. Implications for GeoMind (remote-sensing, researchers/engineers)

GeoMind is local-first + data-sovereign + hybrid LLM (remote default, local GGUF fallback) + SQLite single writer. Apply:

- **No account gate**: app opens to workspace immediately; model/API keys optional & env-based (already invariant). First-run usable offline.
- **"Available offline" granularity**: for rasters/documents, mark assets/pages available offline with download progress; refuse partial render (Notion lesson) — critical for large rasters.
- **Sync status always visible**: local-saved / syncing / confirmed / action-required; pending ops count; conflict surfacing.
- **Model management panel**: discover/install/run local GGUF models with VRAM/RAM hints; OpenAI-compatible local endpoint swap (already hybrid).
- **Quick capture for field notes**: fast note entry without loading full workspace (Obsidian lesson) — researchers capture in field.
- **Exclusions/privacy controls**: explicit folders/assets excluded from embedding/processing (Obsidian lesson) — researchers have sensitive data.
- **Note-first retrieval**: start with selected raster/document, surface related, build small context bundle; don't dump whole workspace into LLM (Obsidian lesson + cost).
- **Plain-file ownership**: exportable formats (GeoTIFF, Markdown, JSON) so data outlives app (long-term preservation ideal).
- **Conflict resolution**: CRDT or at least block-level merge for collaborative docs; LWW acceptable for metadata; surface conflicts for non-text (raster versions).
- **Accessibility**: sync status as text; offline banners non-blocking.
- **Mobile/field**: local capture works offline; sync when connected; show what's ready.

## 8. Quick checklist for startup-grade local-first UX

1. Instant open, no spinner, no login.
2. Local DB primary; sync background; status visible.
3. Offline = full functionality for available data; "unavailable" not "broken".
4. Download progress + offline tab for manageability.
5. Push-based freshness, not polling.
6. Conflict surfacing with both versions preserved.
7. Exclusions/privacy controls explicit.
8. Note-first retrieval, small context bundles.
9. Quick capture path that bypasses heavy load.
10. Exportable plain formats for longevity.
11. Model management UI for local LLMs.
12. Accessible status (text, non-blocking banners).
