# F5 — Onboarding & Empty-State Best Practices for Complex Technical Tools

**Angle:** Onboarding and empty-state best practices for complex technical tools.
**Audience:** Researchers/engineers (remote sensing). Product: GeoMind (data-sovereign AI platform, local-first, hybrid compute).
**Date:** 2026-11-03

---

## 1. Executive Summary

Empty states are the single most overlooked onboarding surface in complex technical tools. For a researcher-facing geospatial AI platform, the empty state is often the screen a new user stares at longest, and "No data yet" with no action is a silent drop-off. Best practice (NN/G, PatternFly, Carbon) converges on: **treat every blank canvas as the next control on the path to "aha," never as an apology.** Combine an instructional empty state ("create first workspace / upload raster / ask a question") with a **demo-data / sample-workspace path** so users can experience value before committing their own data. Layer a short, skippable, behavior-triggered product tour (3–5 tooltips) only over the path to first value, and a persistent but dismissible checklist (3–6 items, first item pre-completed) for multi-step setup. Match guidance intensity to **category familiarity**, not product complexity — researchers have used GIS/QGIS/Earth Engine, so GeoMind needs less "what is a map" and more "where is my first grounded answer."

## 2. Key Findings

### 2.1 Empty states: the core doctrine

- **Describe possibility, not absence.** "You don't have any projects" → drop-off. "Create your first project / import a raster / ask a question" → action. (Rework, Krest, NN/G)
- **An empty state is the next control on the path to aha, not a dead-end.** Name the first creatable object per segment; put the create action on the canvas; point a short tour/checklist at it. (Krest)
- **Audit every screen a brand-new account can reach with zero data.** If any shows a blank state with no guidance, that is a drop-off risk. (Appcues, Rework)
- **Delete empty states that only apologize. Keep the ones that start first work.** (Krest)

### 2.2 NN/G — 3 guidelines for empty states in complex applications

1. **Use empty states to provide learning cues** (in-context, "pull revelations" — show up only when the user interacts). In-context help is more memorable than upfront tutorials because it is applied immediately.
2. **Accurate system-status messages.** Never show "No records" while data is still loading; inaccurate status destroys trust. If a process is running, show progress indicators.
3. **Direct pathways into the workflow.** Provide 1–2 concrete next actions (e.g., Loggly: "add external log sources" OR "populate demo data"). For completed processes with no results, state briefly that no content is available.

### 2.3 Two empty-state strategies (both needed)

| Strategy | When | GeoMind application |
|---|---|---|
| **Instructional** — prompt first action ("Create project", "Upload raster", "Ask a question") | First-use, zero data | Workspace home, document list, raster list, Q&A panel |
| **Demo content / data seeding** — pre-populate so users see the product in use before adding their own data | When value is invisible without data (geospatial!) | "Try with sample Landsat scene" button; pre-seeded demo workspace with a raster + 2 papers + a sample Q&A thread with citations |

Asana/Trello pattern: pre-populated templates give a working example to explore rather than a blank screen. Loggly pattern: offer **both** pathways side by side.

### 2.4 Empty-state taxonomy (PatternFly)

- **First-use / get started** — rocket icon, extra-large, educate + value prop + primary action.
- **No data to show** — search icon; explain *why* (filters, all resolved) + how to move forward.
- **Required configuration** — wrench icon; user must configure/connect/enable before viewing.
- **User not entitled** — lock icon; explain access + how to request.
- **Error** — red exclamation; backend failure.

For GeoMind: "required configuration" maps to "no LLM key configured" and "no workspace selected" states — must be distinct from "no data yet."

### 2.5 Onboarding pattern toolkit (combine 2–4, not all)

From Appcues + Guideflow + SaaSUI:

| Pattern | Use when | Rules |
|---|---|---|
| **Welcome message** | First login | Single CTA, minimal text, modal with transparent backdrop. ~9/10 products start here. |
| **Product tour (tooltips)** | Complex UI, first-use orientation | **3–5 tooltips max**, ≤140 chars, value-focused copy, first tooltip opens on page load, skippable. Behavior-triggered, not page-load. |
| **Progress bar / dots** | Multi-step setup | Start partially filled (sense of progress); honest completion only. |
| **Checklist** | Multi-step first-touch | 3–6 items, lead with value-producing step, first item pre-completed, persistent but dismissible, retire after completion, store progress per user. |
| **Hotspots** | Non-essential features, self-paced | Passive pulsating dots; lower intensity. |
| **Tooltips** | Isolate form fields / setup | Action-oriented, disappear on leave; don't put essential info here. |
| **Persona-based onboarding** | Multiple audiences | 2–5 self-segmentation choices; one checklist per role, not one checklist with grayed tasks. |
| **Progressive disclosure** | Deep feature sets | Stage features across first week (Grammarly model). |
| **Deferred account creation** | Value before commitment | Value first, then signup at logical moment. (Less relevant for GeoMind's research context — account is local.) |

### 2.6 Checklists — specific rules

- Lead with the step that **produces value**, not the easiest to ask for. (SaaSUI)
- **Honest progress**: no padded "20% for signing up"; bar must be able to reach 100%; no erratic jumps. (SaaSUI)
- **Pre-complete the first item** so users feel they've already started. (Userpilot)
- **Retire** the checklist after required items done or on "Hide" — don't bring it back every session. (JustFigma)
- **Skip is a real control** — "I'll do this later" returns to product with empty state still offering first action; don't dump on blank dashboard. (JustFigma)
- **Store progress per person**; refresh must not restart tour; completed = never shown again. (JustFigma)
- **One checklist per role**, not one with grayed tasks. (JustFigma)
- Measure: checklist completion rate, drop-off per step. (Appcues, Pendo)

### 2.7 Product tours — specific rules

- 3–5 tooltips for new-user tours; feature-specific tours can stretch to 7 but watch drop-off. (Guideflow)
- Progress indicators ("Step 2 of 4") improve completion ~12%. (Guideflow)
- Trigger on **behavior**, not page load. (Guideflow)
- Monthly review cadence for high-traffic tours; add tour review to release checklist (onboarding rot). (Guideflow)
- Tours drop to ~16% completion at 7+ steps. Cut anything not serving the activation event. (Guideflow)
- **Don't chain five modals.** Pick one container. (JustFigma)

### 2.8 Geospatial / technical-tool specifics

- **CARTO pattern**: "Getting started steps" on workspace home — Step 1 connect data, Step 2 create map — with demo tables in a data warehouse to explore immediately. GeoMind equivalent: "Try with sample workspace" → seeded raster + documents + a pre-run Q&A.
- **Earth Blox pattern**: short intro video + persona/use-case selection ("what resembles what you want to do") before diving in — good for researchers unfamiliar with remote sensing pipelines.
- **IBM Geospatial Studio pattern**: lab-based onboarding (Lab 1: 10 min beginner → Lab 4: 90 min) — progressive depth, optional. GeoMind can mirror: "Quick start (5 min)" vs "Full walkthrough (30 min)".
- **MGISS (geospatial onboarding vendor)**: simplify complexity, build confidence/trust via shared success stories, hands-on with *your* data, measure activation/time-to-value/retention. Technical audience needs **trust in outputs** (accuracy, explainability) — onboarding must demonstrate provenance early.
- **Azure Maps Creator pattern**: numbered, clearly outlined steps with a final single upload action — good model for "ingest → index → ask" pipeline onboarding.
- **i-Cetech pattern**: 4-phase (Foundations → Technical → Real-time → Integration) with hands-on workshops on *your* data — matches GeoMind's researcher workflow.

### 2.9 Measurement (minimum viable)

Track at minimum (Appcues, Gong, MGISS):
- **Activation rate** (% reaching first key action).
- **Time to first key action** (TTV).
- **Checklist completion rate** + per-step drop-off.
- **Day 7 retention**.
- **Empty-state → action conversion** (did the empty-state CTA get clicked).

GeoMind's "first key action" candidates: (a) first grounded answer with ≥1 citation, (b) first map/raster visualization, (c) first workspace created with data. Recommend (a) as primary activation event since it's the unique value prop.

## 3. GeoMind-Specific Application

### 3.1 Empty states per surface

| Surface | Empty state | Primary action | Secondary action |
|---|---|---|---|
| Workspace home (no workspaces) | "Create your first workspace" + value line | Create workspace | "Try sample workspace" |
| Document list | "No documents yet" | Upload document | "Load sample papers" |
| Raster list | "No rasters yet" | Upload raster | "Load sample Landsat scene" |
| Q&A panel (no history) | "Ask a question about your data" | Focus input + suggested prompts | "See example Q&A" |
| Map view (no layer) | "Add a layer to begin" | Add raster layer | — |
| Search (no results) | "No matches" + broaden tips | Clear filters | — |
| LLM not configured | Distinct "required configuration" state | Configure LLM key | "Use local model" |

### 3.2 First-run sequence (recommended)

1. **Welcome modal** (single CTA) → "Get started" or "Explore sample workspace".
2. **Persona prompt** (optional, 2–3 choices): "Researcher / Analyst / Developer" → tailors suggested prompts and checklist.
3. **Sample workspace offer** (deferred commitment): load a pre-seeded workspace with 1 raster + 2 papers + 1 completed Q&A with citations → user sees value in <60s.
4. **Checklist** (3–5 items, first pre-completed): "✓ Open sample workspace → Upload your first raster → Ask a question → View citation → Configure LLM".
5. **Behavior-triggered tooltips** (3 max) over the path to first grounded answer.
6. **Retire checklist** on completion; convert to "Launchpad" resource hub.

### 3.3 Trust/provenance in onboarding

Researchers need to trust outputs. Onboarding must demonstrate the **citation chain** (answer → citation → segment → asset_revision → object) within the first session — ideally via the sample Q&A where clicking a citation jumps to the source segment and shows the raster. This is GeoMind's differentiator; show it, don't explain it.

### 3.4 Accessibility & RTL

- Web uses shadcn/ui + Tailwind **logical properties** (`ps/pe/ms/me`) for RTL (fa locale). Empty-state illustrations must mirror; icons that imply direction must flip.
- All onboarding copy via i18next (en/fa); Persian register per `persian-writing` skill (formal/technical for research audience).
- Keyboard-navigable tooltips/checklist; skip must be keyboard-accessible.

## 4. Anti-Patterns (avoid)

- "No data yet" with no button (Krest: "a skip they earned").
- Inaccurate "No records" while loading (NN/G: destroys trust).
- Tours narrating every button; >5 steps (Guideflow: 16% completion).
- Chaining five modals (JustFigma).
- Dishonest progress (padded 20% for signup) (SaaSUI).
- One giant checklist with grayed tasks for all roles (JustFigma).
- Leaving empty states as an afterthought / engineering fills "No data yet" (Rework).
- Forcing tutorials upfront instead of in-context pull revelations (NN/G).
- Empty state that disappears only to reappear every session (checklist must retire).

## 5. Implementation Priorities for MVP

P0 (ship with MVP):
1. Instructional empty states on all 6 surfaces (workspace, docs, rasters, Q&A, map, search) with primary + secondary actions.
2. "Try sample workspace" button + seeded demo data (raster + 2 papers + 1 Q&A with citations).
3. Distinct "required configuration" state for unconfigured LLM.
4. Welcome modal with single CTA.

P1 (post-MVP, pre-launch):
5. Persistent dismissible checklist (3–5 items, per-role variant).
6. 3-tooltip behavior-triggered tour over first grounded answer.
7. Persona prompt (researcher/analyst/developer).

P2 (growth):
8. Empty-state → action conversion analytics.
9. Multi-step lab-style walkthrough (IBM Studio model) for advanced users.
10. Onboarding rot review cadence in release checklist.

## 7. Confidence & Gaps

- **High confidence** on empty-state doctrine (NN/G + PatternFly + Carbon converge strongly) and on checklist/tour rules (multiple SaaS sources agree on 3–5 steps, honest progress, retire-on-completion).
- **Medium confidence** on geospatial-specific onboarding (sources are vendor case studies + docs, not controlled studies); recommend validating with 5–10 researcher interviews before committing to sample-workspace content.
- **Gap**: No direct evidence on onboarding for *local-first* AI tools specifically (Ollama/LM Studio onboarding not covered in search results) — recommend a follow-up angle if needed. Assumed local-first onboarding mirrors offline-capable desktop app patterns (sample data bundled, no signup, first-run in <60s).
- **Gap**: Persian/RTL onboarding copy and cultural onboarding expectations not researched; rely on `persian-writing` skill + native review.
