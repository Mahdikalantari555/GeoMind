# F2 — Competitive UX Patterns in EO/Geospatial AI Tools

**Angle:** Competitive UX patterns in EO/geospatial AI tools (Mapbox, QGIS plugins, Google Earth Engine, Descartes Labs, Felt, Google Earth AI).
**Audience:** GeoMind = local-first AI platform for remote sensing research; researchers/engineers.
**Date:** 2026-11-03
**Sources:** Google Earth Engine Code Editor docs (developers.google.com/earth-engine/guides/code_editor_assistant, playground); Mapbox MapGPT + Location Infrastructure for AI pages; Felt AI platform page; Google Earth AI page; QGIS.org landing; Kepler.gl/Felt marketing surfaces.

---

## 1. Executive summary

The competitive landscape splits into **three UX regimes**:

1. **Code-centric IDEs** (Google Earth Engine Code Editor): left panel = scripts/assets/docs, center = code + map, right = inspector/console/tasks/profiler/Ask. AI is a *side panel* (Ask tab) with explicit tool toggles, automatic script context, and a "Troubleshoot" bridge from console errors. Strong for researchers who code; weak for non-coders.
2. **Conversational map copilots** (Felt AI, Google "Ask Google Earth", Mapbox MapGPT): natural-language input → map/layer/result. The AI *does the work* (finds data, runs analysis, builds layers) and narrates steps in plain language. Strong for "anyone can ask"; the map is the answer, not the code.
3. **Desktop GIS + plugin ecosystem** (QGIS): toolbox + layers + canvas; AI arrives via plugins; extensibility via Python. Powerful but click-heavy; the "weeks to months per custom feature" pain Felt explicitly attacks.

**GeoMind's opportunity:** combine regime 1's *auditable, citation-grounded* provenance with regime 2's *plain-language, narrated* analysis and regime 3's *local-first, extensible* data sovereignty. The differentiator is the **provenance chain** (answer → citation → segment → asset_revision → SHA-256) surfaced as first-class UX, which none of these competitors expose.

## 2. Google Earth Engine Code Editor

### 2.1 Overall layout (the canonical "code + map" split)

From the Code Editor guide (developers.google.com/earth-engine/guides/playground):

- **Left panel (tabs):** Docs (API reference), Scripts (Script Manager / Git repos), Assets (Asset Manager).
- **Center:** JavaScript code editor (syntax highlight, autocomplete, problem underlines, pairs).
- **Top of editor:** Run, Save, Reset map/console, Get Link (snapshot vs saved script URL), Import.
- **Map display:** visualizes geospatial datasets; Layer Manager (upper right) toggles visibility + transparency slider + visualization params (stretch, gamma, palette). Background toggle to right of Layer Manager. Geometry drawing tools upper-left of map.
- **Right panel (tabs):** Inspector (click map → location + pixel values + objects, crosshair cursor), Console (printed output, expandable), Tasks (long-running import/export, Run button, config dialog), Profiler (resource usage table), **Ask (AI assistant)**.
- **Top search bar:** "Search places and datasets…" → places + raster/table datasets → import directly.
- **Imports section** at top of script (hidden until import), copyable to other scripts.
- **Geometry Imports** on map + in Imports; layer settings dialog; lock layer.

Key UX lessons:
- **Tabbed right panel keeps map always visible** while switching context (inspector/console/tasks/ask) — no navigation away from the map.
- **Layer Manager is a floating overlay on the map**, not a separate panel — keeps visual context.
- **Long-running ops are explicit tasks** with a Run button + config dialog (ctrl/⌘+Run skips dialog) — user controls submission.
- **"Get Link" with snapshot vs saved** distinguishes reproducibility (snapshot = frozen environment incl. code, imports, layers, map position; saved = always latest).
- **Geometry drawing on map → auto-import** lowers friction for AOI selection (researchers draw, don't type coords).

### 2.2 AI assistant — "Ask" tab (the most relevant competitor UX)

From developers.google.com/earth-engine/guides/code_editor_assistant:

**Location:** right-hand pane, tab next to Inspector/Console/Tasks.

**Controls:**
- Send/Stop (toggles to stop icon during generation; Enter to send).
- New chat (clears history, fresh session).
- Help (dialog: feature info, billing, terms).
- **Model selection dropdown** (choose Gemini model; saved per session).
- **Tool toggles menu** (enable/disable Docs, Dataset search, Google Search) — saved per session. Google Search mutually exclusive with Docs/Dataset search (UI disables others).
- Copy (code blocks) and **Insert** (into script editor; if editor not empty → diff dialog highlighting changes for review).
- Regenerate (retry button at bottom of last response).
- **Token counter** (tokens used in current session vs API key limits).

**Automatic context (every request):**
- Full text of current script.
- Imported assets and geometries.
- Chat history of current session.

**Error bridge (key pattern):** Console error → red error card → "Troubleshoot" button → auto-opens Ask panel with auto-generated prompt containing error message + relevant script context. User reviews/sends.

**Tool options (each adds context, costs tokens):**
- Docs: searches Earth Engine public docs.
- Dataset search: searches Earth Engine Data Catalog.
- Google Search: grounds in web results.

**Prerequisites:** user's own Gemini API key; key icon in chat input → paste + optional save for future sessions. Billing/costs surfaced (free vs paid tier, spend cap in AI Studio).

**Data/privacy:** Gemini API Terms; prompts/content handled per those terms.

**Feedback:** feedback button upper right → "Send Code Editor feedback."

**Example prompts categorized:** code generation/workflows, Earth Engine Apps, debugging, explanation, optimization.

**GeoMind-relevant takeaways:**
- **Tool toggles with cost transparency** (token counter + "enabling tools adds context → more tokens") — researchers want control over cost/quality tradeoff.
- **Insert-with-diff** (not blind overwrite) — critical for code trust; user reviews changes before accepting.
- **Error→assistant bridge** ("Troubleshoot" on red error card) — turns failures into guided recovery; high value for researchers.
- **Automatic script context** — assistant always knows what you're working on; no manual copy-paste.
- **Model selection persisted** — user preference survives sessions.
- **BYO API key with in-product config** (key icon in input) — GeoMind already supports env-based keys; in-product paste is the UX to mirror for local GGUF/remote keys.

## 3. Mapbox — conversational + location infrastructure

### 3.1 MapGPT (location-intelligent AI assistant)

From mapbox.com/mapgpt:

- **Natural, human-like conversations** — no precise commands; interprets partial info, statements, open-ended questions; multi-language.
- **Deeply integrated with navigation software** + live Mapbox data.
- **Action library** for drivers: search destinations, control navigation, play music, vehicle-system actions (battery, temperature), partner integrations (restaurant bookings accounting for travel plans, range, preferences).
- **Seamless transition to chat** — continue conversation before/during/after trip across in-vehicle + mobile.
- **Customizable:** name, wake word, avatar, personality, voice; modular components (preferred LLM + voice vendors); ingest custom data sources (owner's manual, dealer locations, EV charging networks).
- **Onboard Tiny LLM** runs on embedded hardware for essential conversations without internet.
- Marketing: "first AI assistant that can have natural conversations about location."

UX lessons for GeoMind:
- **Partial/open-ended input accepted** — don't force structured queries; accept "show me X near Y" phrasing.
- **Action-oriented assistant** (does things, not just answers) — GeoMind's agent should run analysis, not just describe.
- **Custom data ingestion into assistant** (owner's manual analogy → GeoMind: ingest workspace docs/rasters into assistant context).
- **Offline-capable small model fallback** (Tiny LLM) — GeoMind already has local GGUF fallback; surface it as "works offline" UX.
- **Cross-device continuity** (in-vehicle ↔ mobile) — GeoMind could offer web ↔ (future) mobile continuity for field researchers.

### 3.2 Location Infrastructure for AI (Mapbox platform)

From mapbox.com/location-infrastructure-for-ai:

- **Three audiences:** applications (APIs/SDKs add spatial intelligence), agents (conversational agents reason + interact with location like a human), developers (coding agents build location experiences).
- **Natural language search** in Search Box API; location-aware voice assistants (MapGPT).
- **Agentic Mapping Engine:** combines open-source + licensed data + real-time signals from Mapbox-built apps → living map; provides foundation for spatial intelligence.
- **Coding-agent integration:** install Mapbox CLI → prompt Claude Code/Codex/Cursor to build complete location-powered apps from scratch. Mapbox MCP server for ChatGPT/Claude.
- **Natural Language Queries** in Search Box API (blog referenced).
- **Places API** new.

UX lessons:
- **Natural language as a first-class input modality** across the platform, not just chat.
- **Agent/MCP integration** as distribution channel — GeoMind's agent tools could be exposed via MCP for external AI assistants (Felt does this too).
- **"Applications become instantly agentic"** — AI baked into platform primitives, not a bolt-on panel.

### 3.3 Mapbox Studio (visual style editor)

From docs.mapbox.com/mapbox-studio:

- **Basemap choice first** (Mapbox Standard vs Standard Satellite), with themes (Default/Faded/Monochrome).
- **Imports panel** for customizing basemap colors/fonts/key visual properties.
- **Publish** to make style available in production; style URL referenced in apps.
- Style = JSON document (Mapbox Style Spec); Studio is visual editor over it.
- Layers panel, toolbar, publishing options (interface guide).

UX lessons:
- **"Choose basemap, then customize"** two-step reduces decision fatigue.
- **Publish as explicit action** with a shareable URL — GeoMind should have "publish workspace/export" as explicit, not implicit.
- **Style URL as contract** between design and runtime — GeoMind could expose "workspace snapshot URL" for reproducibility.

## 4. Felt — conversational GIS (strongest "AI does the work" UX)

From felt.com + felt.com/platform/felt-ai (very rich):

### 4.1 Core UX promise
"GIS expertise, a prompt away." Ask in plain language; Felt finds data, runs analysis, builds map/dashboard/tool, showing each step. Anyone on team asks; no GIS training needed.

### 4.2 Felt AI interaction pattern (the reference for "narrated analysis")
Example flow (wind turbine suitability):
1. User prompt: "Where should we build our next wind farm?"
2. AI narrates steps in plain language as they run:
   - "Found 1 layer · CAL FIRE Fire Hazard Severity Zones" / "Zonal mean wind speed for 3,109 counties"
   - "Joined USGS turbines and transmission lines"
   - "Scored 3,109 counties on four factors · kept top 25"
3. Result layer created and marked **"live"** (editable layer, not a static answer).
4. **Bold bottom-line summary** in natural language: "The Dakotas are your answer. Buffalo and Minnehaha clear 7.8 m/s…"
5. Layer becomes a persistent, editable artifact in the workspace.

Additional examples:
- Flood exposure: "Which of our sites are in the 100-year floodplain?" → joins FEMA flood zones to 13 sites → "4 of your 13 sites are in it…"
- Crew dispatch: "A line's down on Route 28… who should we send?" → routes 4 crews on roads → "Send Crew 2, 3 minutes out… Crew 1 is closer as the crow flies (2.3 km) but across the reservoir: 9 minutes by road." (shows reasoning, not just answer)

### 4.3 Key UX patterns

- **Step narration in plain language** (not code, not spinners) — each step names data source + operation + count. This is the "research steps" pattern (cf. Perplexity) but for geospatial analysis.
- **Result as a live layer**, not a text answer — the AI produces a workspace artifact you can edit/share. "is live" badge signals mutability.
- **Bottom-line natural-language summary** bolded, separate from step log.
- **"It builds, not just suggests"** — custom tools/popups/extensions written by AI on request ("Build the tools your team has been waiting for"). Popups with stats/charts; SQL shown for review.
- **SQL transparency** — analysis shows its SQL and steps so users can review ("Spatial analysis and SQL, in plain language"). Database queries are read-only.
- **MCP server** (hosted, cloud) — 30 tools in 6 groups; any MCP-compatible AI (Claude/ChatGPT/Gemini/Copilot/Cursor) can drive Felt; inherits user permissions; data stays in warehouse (SQL runs there). "One hosted endpoint, nothing to install." Dialect-aware SQL guidance. Available Business/Enterprise.
- **Agent loop diagram** (visual): Your AI tool → Felt MCP server → tools it calls → your warehouse → live Felt map. Clear mental model of where compute/data live.
- **Permissions inheritance** — agent sees only what user can see; maps governed by workspace controls. Trust via access control, not just UX.
- **Privacy trust statements:** frontier models via Amazon Bedrock; never trained on your data; conversations private unless shared; only reachable data.

### 4.4 Empty/onboarding (from F5 already; Felt specifics)
- "Getting started steps" on workspace home: Step 1 connect data, Step 2 create map (CARTO-style).
- Demo content: pre-populated maps (map gallery) show value before own data.
- "Try with sample workspace" implicit via gallery.

### 4.5 Collaboration UX
- Real-time collaborative editing on same map; comments; share links without login; embed.
- Field app (iOS/Android) offline capture → syncs to shared map.

### 4.6 Geospatial analysis affordances
- Ready-made data (Census, boundaries, flood risk, roads, buildings).
- Drive-time areas, H3 hexagons, spatial analysis (buffer/clip/intersect/count), geocoding up to 10k addresses, print layouts, GIS exports (GeoPackage/Shapefile/GeoJSON/CSV).
- Raster streaming at full resolution.

**GeoMind-relevant takeaways:**
- **Step narration as first-class UX** — GeoMind's agent should narrate retrieval/analysis steps in plain language (not just final answer), naming data sources + counts. This is the "research steps" pattern applied to geospatial work.
- **Result as persistent artifact (live layer)**, not ephemeral chat answer — GeoMind's answers should land as workspace objects (map layers, documents, citations) that persist and are editable.
- **SQL/analysis transparency** — show the query/operation behind an answer for researcher audit (GeoMind already has provenance chain; surface it as "steps" not just final citation).
- **MCP server as distribution** — expose GeoMind's agent tools via MCP so external AI assistants can drive GeoMind workspaces (Felt's model). Fits local-first if server runs locally.
- **Permissions inheritance for agents** — agent acts with user's access; never bypass workspace controls.
- **"It builds, not just suggests"** — agent should create artifacts (layers, popups, tools), not just describe.

## 5. Google Earth AI / "Ask Google Earth"

From ai.google/earth-ai:

- **"You Ask, The Earth Answers."** — natural language queries over Earth observation data.
- **Ask Google Earth** (in Google Earth): explore world in plain language; chat panel with data table + map pins (image shows chat panel + data table + map pins). Deep analysis capabilities for Professional/Professional Advanced users (US).
- **Geospatial Reasoning agent** (experimental): connects Earth AI capabilities (satellite imagery analysis, weather forecasting, routing, predictive modeling) to custom agents / Cloud workflows in Gemini for business. "Express interest" gating.
- **Imagery models**: search Earth with natural language — object detection, scene classification, change detection across imagery (e.g., harmful algae blooms in drinking water). Significantly accelerates remote-sensing workflows.
- **AlphaEarth Foundations**: unified representation of EO data (Satellite Embedding Dataset, 10m pixels, annual) for faster analysis.
- **Planetary prediction engine**: train custom predictive models with simple prompts + Earth AI embeddings.
- **WeatherNext 3** global weather forecasting.

UX lessons:
- **Chat panel + data table + map pins** triad (chat answer, tabular results, spatial pins) — three views of same result. GeoMind should offer answer + table + map as coordinated views.
- **Natural language over imagery** ("search the earth using natural language") — GeoMind's vision modality should support "find X in this scene" style queries.
- **Gating advanced features by tier** (Professional/Professional Advanced) — GeoMind can tier compute-heavy analysis.
- **"Express interest" for experimental agents** — honest capability gating; don't over-promise.

## 6. QGIS (desktop GIS + plugin ecosystem)

From qgis.org landing:

- **Four pillars:** Create maps (cartography, layout designer, atlases/reports), Edit layers (digitizing, CAD-like tools, forms), Process & analyze (toolbox, visual workflows/model builder, extensible via plugins), Share (format support, standards, web/mobile publishing).
- **Visual workflow builder** — combine analysis tools into reproducible workflows (model builder).
- **Plugin ecosystem** — third-party analysis tools; extensible analysis environment.
- **Form designer** for user-friendly attribute editing.
- **Free & open source**, community-driven; sustaining members.

UX lessons (and anti-lessons):
- **Toolbox + model builder** = reproducible, inspectable pipelines — researchers value inspectability; GeoMind's agent steps should be reproducible like a model builder graph.
- **Plugin extensibility** is the moat for power users; GeoMind could allow custom tools/plugins (agent tools registered like QGIS plugins).
- **Anti-lesson:** "click heavy and cumbersome," weeks-to-months per custom feature (Felt's critique). GeoMind must avoid click-heavy workflows; AI should collapse multi-step GIS ops into one prompt + review.
- **Desktop-first** means no account gate, works offline — aligns with GeoMind local-first; but web delivery (GeoMind) is the modern default. Keep desktop-grade power in browser.

## 7. Kepler.gl (referenced; not deeply fetched)

Kepler.gl is the standard open-source WebGL geospatial viz tool (Uber). Known UX patterns: layer panel with per-layer styling (color/size/opacity), filter panel (time, value ranges), tooltip config, 3D extrusion, animation by time. Commonly embedded in AI/geospatial apps as the map canvas. GeoMind can adopt Kepler-style layer/filter panels for its map view, but keep AI-driven layer creation (Felt-style) as primary entry.

### 8.3 Trust/provenance patterns (GeoMind's moat)
- **Provenance chain** (answer → citation → segment → asset_revision → SHA-256) is unique to GeoMind; competitors link to URLs or live layers but don't expose content-addressed audit trails. Surface it as first-class UX (chain-of-custody panel, export for papers).
- **Verification step** between generation and render (flag unsupported claims) — from F3; none of the competitors visibly do this; opportunity.
- **Per-claim grounding levels** (fully cited / synthesis-informed / uncited) — GeoMind can lead here.

### 8.4 Data & collaboration patterns
- **Real-time collaborative editing + comments + share links without login** (Felt) — GeoMind web could adopt for research teams.
- **Field/offline capture → sync** (Felt field app) — GeoMind researchers capture in field; local-first already supports this.
- **Warehouse-native SQL (data stays put)** (Felt MCP) — GeoMind's data-sovereign model: data never leaves local; LLM compute hybrid.
- **Exportable plain formats** (GeoPackage/Shapefile/GeoJSON/CSV/GeoTIFF/Markdown) — long-term preservation (local-first ideal).

## 9. Implications for GeoMind (startup-grade, research audience)

### P0 (ship with MVP)
1. **Adopt the "code + map + tabbed side panels" layout** (Earth Engine) with map always visible; tabs: inspector/console/tasks/ask (or GeoMind equivalents: data, console, jobs, assistant).
2. **Floating Layer Manager** on map for toggle/opacity/vis params.
3. **Assistant as a side tab** with: auto-context (active workspace/raster/document), tool toggles (docs/dataset/web) with token/cost counter, model selection persisted, BYO key in-product (key icon), Insert-with-diff for code/doc edits, Error→assistant bridge (Troubleshoot button on error cards).
4. **Step narration** in the assistant (Felt pattern): narrate retrieval/analysis steps in plain language naming sources + counts, not just final answer.
5. **Answers land as persistent workspace artifacts** (live layers/documents), not ephemeral chat.
6. **Natural-language input accepted loosely** (partial/open-ended) across search/assistant.
7. **Geometry drawing → auto-import** for AOI selection.

### P1 (post-MVP, pre-launch)
8. **Chat panel + data table + map pins triad** (Ask Google Earth) for coordinated result views.
9. **SQL/analysis transparency** in assistant (show query/operation behind answer) — feeds researcher audit.
10. **MCP server** exposing GeoMind tools so external AI assistants can drive workspaces (Felt/Mapbox model); permissions inheritance.
11. **"It builds, not just suggests"** — agent creates layers/popups/tools on request.
12. **Natural-language imagery search** ("find X in this scene") for vision modality.
13. **Tiered gating** for compute-heavy analysis.

### P2 (growth)
14. **Visual workflow/model builder** (QGIS) for reproducible, inspectable pipelines — export as reusable workflow.
15. **Plugin/tool registration** for power users (custom agent tools).
16. **Real-time collaboration + comments + share links** (Felt).
17. **Field/offline capture → sync** mobile companion.
18. **Chain-of-custody panel + provenance export** (GeoMind's moat; from F3) — answer→citation→segment→asset_revision→SHA-256 with timestamps/creator, exportable for papers.
19. **Per-claim grounding levels + verification step** (from F3) — lead the market on trust calibration.

### What to skip (competitive anti-patterns)
- Click-heavy multi-step GIS workflows (QGIS pain; Felt's critique) — AI should collapse ops.
- Code-only UX with no plain-language path (Earth Engine barrier for non-coders) — GeoMind needs both.
- Ephemeral chat answers that don't persist as workspace artifacts (most chatbots) — answers must land as objects.
- AI that only suggests, never builds (Felt's "it builds" differentiator).
- Blind overwrite of user code/docs (no diff) — always review changes.
- Hiding retrieval/analysis steps (trust theater) — narrate steps.
- Over-promising experimental capabilities without gating (Google Earth AI "express interest" is the honest pattern).
