# Research Brief: Startup-Grade GeoMind Product & UX

Date: 2026-11-03

## Question
What must the final GeoMind app be, from a user's point of view, to become a real startup product? Need comprehensive user stories, feature set, and best-in-class UX patterns for a data-sovereign AI platform for remote sensing research.

## Scope (in)
- User personas: remote sensing researchers, GIS analysts, data engineers, ML practitioners.
- Core jobs: ingest documents/rasters, search, grounded Q&A with citations, map/farm analysis, agent automation, feedback loop.
- UX patterns for trust, provenance, offline-first, onboarding, empty states, command palette, accessibility.
- Competitive landscape: Earth observation AI tools, local-first AI apps, citation-grounded RAG products.
- Feature prioritization for startup MVP vs advanced.

## Scope (out)
- Implementation details of libs (already specified).
- Deep academic evaluation of models.

## Assumptions
- GeoMind remains local-first, hybrid compute.
- Target users are technical researchers, not casual consumers.
- Startup viability requires clear onboarding, trust, and a feedback flywheel.

## Depth mode
standard (3-5 sub-agents, 15+ sources)

## Angles
1. User personas & jobs-to-be-done for remote-sensing AI platforms.
2. Competitive UX patterns in EO/geospatial AI tools (Mapbox, QGIS plugins, Google Earth Engine, Descartes Labs, etc.).
3. Trust/provenance UX in citation-grounded AI (Perplexity, Elicit, SciSpace).
4. Local-first/offline AI app UX (Ollama, LM Studio, Obsidian, Notion offline).
5. Onboarding & empty-state best practices for complex technical tools.
